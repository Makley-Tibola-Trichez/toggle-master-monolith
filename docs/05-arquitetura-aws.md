## Visão geral

A aplicação roda em uma única instância EC2 na sub-rede pública e acessa um banco PostgreSQL no Amazon RDS, em sub-rede privada, dentro de uma VPC. As credenciais do banco são gerenciadas pelo AWS Secrets Manager e acessadas pela EC2 através de uma IAM role.

```
Clientes da API ──HTTP :5000──►┐
                               │   Internet Gateway
Administrador ───SSH :22─────►┤
                               ▼
┌──────────────── VPC 10.0.0.0/16 · us-east-1 · AZ us-east-1a ─────────────────┐
│  Sub-rede pública 10.0.0.0/20            Sub-rede privada 10.0.128.0/20      │
│  ┌───────────────────────────┐           ┌───────────────────────────┐       │
│  │ EC2 (app Flask+Gunicorn)  │──5432────►│ RDS PostgreSQL            │       │
│  │ SG-ec2-togglemaster       │           │ SG-db-togglemaster        │       │
│  │ Instance profile ─ IAM    │           └───────────────────────────┘       │
│  └───────────┬───────────────┘                                               │
└──────────────┼───────────────────────────────────────────────────────────────┘
               └──► AWS Secrets Manager (credenciais, via IAM role)
```

## Componentes

| Componente | Detalhe (conforme o diagrama) |
| :-- | :-- |
| Região / zona | `us-east-1` (N. Virginia). O diagrama mostra a zona `us-east-1a`; a VPC foi provisionada com sub-redes em duas zonas de disponibilidade |
| VPC | `togglemaster-vpc`, `10.0.0.0/16`, criada pelo assistente "VPC e mais", com resolução de DNS e nomes de host DNS habilitados |
| Sub-rede pública | `10.0.0.0/20`, nome `togglemaster-vpc-subnet-public-1a`; abriga a EC2. Tabela de rotas com saída pelo Internet Gateway |
| Sub-rede privada | `10.0.128.0/20`, nome `togglemaster-vpc-subnet-private-1a`; abriga o RDS. Sem rota direta para a internet |
| Internet Gateway | Dá acesso de entrada e saída da internet à sub-rede pública |
| NAT Gateway / VPC Endpoints | Nenhum, para evitar custo adicional (uso do free tier) |
| EC2 | `togglemaster-ec2-postech-fiap`, Ubuntu Server, tipo `t4g.micro` (ARM64/Graviton), EBS raiz de 8 GB gp3, IP público, chave `.pem` para SSH. Executa a aplicação (Gunicorn na porta 5000) |
| RDS | PostgreSQL, classe `db.t4g.micro`, 20 GB gp3, Single-AZ, sem acesso público, grupo de sub-redes `togglemaster-db` (sub-redes privadas em duas zonas, exigência do RDS), porta 5432 |
| IAM role | `togglemaster-rds-secrets`, associada à EC2 por *instance profile*; permite ler o segredo do banco e usar a chave KMS para descriptografá-lo via Secrets Manager |
| AWS Secrets Manager | Segredo criado pelo RDS ao habilitar o gerenciamento das credenciais master; guarda `username` e `password` |

## Security Groups

### `SG-ec2-togglemaster` (EC2)

| Sentido | Protocolo / porta | Origem / destino | Finalidade |
| :-- | :-- | :-- | :-- |
| Entrada | TCP 22 (SSH) | IPs dos administradores | Acesso administrativo |
| Entrada | TCP 5000 | `0.0.0.0/0` | Acesso dos clientes à API |
| Saída | Todo o tráfego | `0.0.0.0/0` (padrão) | Instalação de pacotes, acesso ao RDS e ao Secrets Manager |

### `SG-db-togglemaster` (RDS)

| Sentido | Protocolo / porta | Origem | Finalidade |
| :-- | :-- | :-- | :-- |
| Entrada | TCP 5432 (PostgreSQL) | `SG-ec2-togglemaster` | Só a EC2 consegue conectar ao banco |

O RDS não aceita tráfego da internet nem de outros IPs: a regra referencia o Security Group da EC2, e não um bloco CIDR.

## Fluxos

**Requisição do cliente**: cliente → internet → Internet Gateway → EC2 (porta 5000, Gunicorn/Flask) → RDS (porta 5432) → resposta pelo mesmo caminho.

**Administração**: administrador → SSH (22), restrito aos IPs liberados no Security Group → EC2.

## Gestão de credenciais

A senha do banco não fica no código, no repositório nem gravada na EC2:

1. O RDS gerencia a senha master no Secrets Manager. O segredo guarda apenas `username` e `password`, criptografados com KMS.
2. A EC2 acessa o segredo pela IAM role `togglemaster-rds-secrets` (*instance profile*), sem chaves de acesso na máquina.
3. Na EC2, usuário e senha são lidos do segredo e exportados como variáveis de ambiente; host, porta e nome do banco são exportados diretamente:

```bash
export DB_HOST='<endpoint-do-rds>'
export DB_PORT='5432'
export DB_NAME='postgres'

SECRET=$(aws secretsmanager get-secret-value \
  --secret-id '<arn-do-segredo>' \
  --region us-east-1 \
  --query SecretString --output text)
export DB_USER=$(echo "$SECRET" | jq -r .username)
export DB_PASSWORD=$(echo "$SECRET" | jq -r .password)
```

Observações:

- O código da aplicação não chama o Secrets Manager; ele apenas lê `DB_HOST`, `DB_NAME`, `DB_USER` e `DB_PASSWORD` (`app.py:9-12`). `DB_PORT` é exigida pelo `entrypoint.sh`.
- A rotação automática da senha (padrão: 7 dias) foi desativada para que a senha continue válida e as variáveis não fiquem desatualizadas.
- As variáveis exportadas existem só na sessão do terminal; em uma nova sessão (após logout) os comandos precisam ser executados novamente.
- O ARN é colocado entre aspas simples por causa do caractere `!` no nome do segredo.

## Alinhamento com o enunciado

| Exigência do enunciado | Situação no diagrama |
| :-- | :-- |
| VPC com sub-redes pública e privada | Atende |
| EC2 na sub-rede pública | Atende |
| RDS na sub-rede privada | Atende |
| SG da EC2 permitindo HTTP/HTTPS e SSH de IP específico | **Parcial**: SSH restrito a IPs de administradores; a API é exposta em TCP 5000 (`0.0.0.0/0`), sem HTTPS |
| SG do RDS permitindo apenas o SG da EC2 | Atende |

## Limitações da arquitetura

- **Sem alta disponibilidade**: a EC2 e o RDS (Single-AZ) ficam em uma única zona (`us-east-1a`); uma falha dessa zona derruba o serviço. A escolha reduz custo.
- **Instância única**: não há balanceador nem *auto scaling*.
- **Sem TLS**: o tráfego entre cliente e API trafega em HTTP puro na porta 5000.
- **Porta de aplicação aberta ao mundo**: a API fica diretamente exposta, sem proxy reverso.
- **Saída irrestrita**: a regra de saída padrão permite todo o tráfego.
- **IP público dinâmico**: o IP da EC2 muda ao parar e iniciar a instância, a menos que se associe um Elastic IP.
